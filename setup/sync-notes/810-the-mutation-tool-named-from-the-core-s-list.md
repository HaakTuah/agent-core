- **23 November 2026, the mutation tool named from the core's list.** Done when the manifest's row *mutation tool* is what the core's list gives the project (#1107; `core/tasks/code-shape.md`, "How strong the tests are is measured on the lines a pull request changes"), or holds a command or a `none` of the project's own, which stays. The list (`core/scripts/mutation-tools.json`) names a tool by the languages of the project's code and whether it has tests: Stryker for JavaScript and TypeScript whose tests run by `node`, through `core/scripts/stryker.mjs`; for C#, Python, another test runner, code in the languages of two tools, or no tests yet, `none` with the reason. `node core/scripts/mutation-tools.mjs` prints what it read and the row; with `--write` it writes the row, and for Stryker the package list of `checks/mutation/` where there is none, and says what is left: the lock file (`npm install --package-lock-only --ignore-scripts --prefix checks/mutation`) and the install in the job that runs `strength.mjs`. A row of the manifest, a package list and its lock file: the trusted builder's (floor rule 3). Until Stryker is installed in the job, the strength check says it did not measure and fails nothing, and until the baseline stands it fails nothing either. To keep the measure off, the owner writes `none` with a reason of the owner's own, which no run of the script writes over.
