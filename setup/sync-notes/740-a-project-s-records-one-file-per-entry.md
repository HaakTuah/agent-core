- **19 November 2026, a project's records one file per entry.** Split, once, each record of the project's that its pull requests keep adding to, entry by entry (a line, a row or an item each), as `tasks/planning.md`, "A record pull requests keep adding to is a folder of one file per entry", says (#750, point 1): a running table in its *progress file*, its own archive, a log of its releases. Each becomes a folder of one file per entry, each file named to stand between its neighbours, and whatever reads the record (a script, a check, a rule file that points to it) reads the folder in the order of the files' names, so that two pull requests that add an entry never edit the same lines. Where the order of a record's lines is what it records, as the *progress file*'s is, its lines stay in one file and leave in a batch, as `roles/shared/inbox.md` says of the *progress file*; nothing to split there. A record is such where two of the project's pull requests merged in one week each added an entry to it (`git log --since="1 week ago" --name-only` shows them). What a record holds and the order it is read in stay as they were. Nothing fails or waits while a record stands whole: no check reads which records these are, since that is a reading of the project's history. The cost: a read of which records the project's pull requests keep adding to, and one pull request of a builder's that splits them, with what reads them.
