- **22 November 2026, one process writes what the core owns.** Nothing to do by hand (#1083). From this sync on, the sync, once it writes the copy, runs the one process the starter kit runs too (`core/scripts/converge.mjs`; the core's `AGENTS.md`, "One process takes the core in"): it writes, whole, each workflow, Dependabot config, issue form, hooks' settings and tool entry file the kit writes where it is not there, carries the core's mark (a first line that says so, in a workflow and Dependabot's config) or is what a kit writes for the project, and the core's part of `AGENTS.md` and `CLAUDE.md`, between two marks, every word outside it kept; any other such file it leaves as it is and names as a difference, as it does each file the manifest's "Differences" names. A sync pull request that carries what it wrote stays a pure sync (`core/scripts/pure-sync.mjs`, run from the core's `main`; floor rule 8), so the workflow changes a release brings need no review in the project. The sync that brings this runs the earlier copy's sync script, which does not run the process: the session that syncs runs `node core/scripts/sync.mjs <the manifest's pin>` once more in the sync's branch, which at the same pin moves nothing and runs the process with the earlier kits, and commits what it writes in the sync's pull request. A pull request that afterwards changes a file or part the core marks so that it is not as the core writes it fails the copies part's check, saying the mend. Done when `AGENTS.md` and `CLAUDE.md`, where they stand, hold the core's part between its marks, which the process writes at its first run.
