From this sync on, the workflow check (`core/scripts/workflows.mjs`) runs two maintained tools on each workflow of the project's (`.github/workflows/`) and each action of its own, as `core.yml` and `copies.yml` at the new pin fetch them in their job's set-up (`core/scripts/workflow-tools.sh`): zizmor, which audits for what floor rule 2 forbids and more (untrusted text in a script, an action of another's not pinned to a full commit SHA, a token a checkout keeps), and actionlint, which reads a workflow as GitHub does, a key given twice among what it refuses, with the core's policy as their configs (`core/scripts/zizmor.yml`, `core/scripts/actionlint.yml`). A pull request that adds a finding fails, saying its mend; a finding the pull request's base already held is noted and passes, so each that stands is listed on every pull request's run and on every run on `main`, the base standing as the list. A finding the project judges safe on one line is allowed by a comment `# zizmor: ignore[<audit>]` there, with why beside it. The check's own search for `pull_request_target`, and for a call of the core's checks a draft skips, stay as they were. A project that changes nothing of its workflows changes nothing.
