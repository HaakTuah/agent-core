# One Node for every cloud machine

The owner asked tonight whether anything was still duplicated between the games or departed from the core. A full
audit found each game installing Node on its cloud machines its own way. Amarna's setup fetched the official binary
with `npm pack` and checked its SHA-256. Snakes' setup ran `npm install -g node@26.12.1`, which runs that package's
install script (`preinstall`, which pulls the binary in through node-bin-setup): a break of floor rule 15 on every Snakes
cloud session, since those machines come with Node 22. The two also pinned different versions (26.13.0 and 26.12.1).

- **`scripts/node.sh`:** Amarna's checked install, moved here as the one place for the pin and its checksums. It
  runs no package's install script, takes only the binary out of `node-linux-<arch>`, checks it before it runs, and
  exits 0 whatever happens, saying what it could not do. Tested on a copy of a Node 22 binary: it installed 26.13.0
  (checksum OK), and a second run found it present. 26.13.0 is the newest 26.x, out on 29 October, so past floor
  rule 7's week; `node-linux-x64@26.13.0` and `node-linux-arm64@26.13.0` declare no scripts.
- **`modules/updates.md`, "Node":** the cloud's Node comes from it, and every project's cloud setup runs it.

What changes in every project: its cloud setup runs `core/scripts/node.sh` from its copy on `main`, in place of its own
Node install, in the PR that follows this one's sync.

Readings taken: the pin stays at Amarna's 26.13.0, the newer of the two. Questions for the owner: none.
