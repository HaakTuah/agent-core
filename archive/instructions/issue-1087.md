# The reasons behind the core: issue #1087

The index, and how an item is written: `archive/instructions.md`.

#1087. **22 November 2026**, #1087, a design the owner agreed to in a chat session with the adviser, and confirmed the
     same day. The reading of a project against the core asks too what the project holds twice or against the core:
     a rule that contradicts or loosens one of the core's, one that says what the core's says in other words, a rule
     stated twice in its own files, a check that does a core check's job, and what an older layout of the core left.
     Scripts find first all they read exactly and correct only what is exact, listing what reads close for the
     auditor, who reads it by meaning; the session takes out what says the same and keeps, declared, what differs.
     A project that held its own rules before taking the core keeps rules the core now holds, read twice by every
     session, and they drift apart; a script that corrected what only reads close would have to guess what a rule
     meant. It stands behind "The reading asks what a project holds twice" in `tasks/cleaning.md`.
